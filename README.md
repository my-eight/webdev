# Сайт услуг

Русскоязычный сайт: разработка, внедрение МойСклад и автоматизация, графический и бренд-дизайн.

Nuxt 4, Vue 3, TypeScript. МойСклад — электрический синий `#0134FF`, разработка — лайм `#C6FF36`, дизайн — фуксия `#FE00FF`. На главной нет персональных имён вне контактного блока Славы; на страницах направлений имя в шапке соответствует исполнителю.

## Локальный запуск

Требуется Node.js `^22.22.3 || ^24.15.0 || >=26.0.0` и pnpm 11.25.0.

```shell
cd frontend
pnpm install
pnpm dev
```

Согласованные публичные контакты находятся в `frontend/shared/config/contacts.ts`. Телефон, Telegram и почта Славы показываются на главной и страницах его направлений; на странице дизайна указан Telegram Эрин. Значения можно переопределить через переменные из `frontend/.env.example`; пустое переопределение скрывает соответствующую ссылку. Реальный `.env` не включается в репозиторий. Настройка домена также описана в примере окружения. После изменения конфигурации контактов перезапустите `pnpm dev`, чтобы обновить значения в локальном приложении.

Контактный блок ведёт напрямую в Telegram (`https://t.me/…`), приложение звонков (`tel:`) или создание письма (`mailto:`). Данные формы на сервер не отправляются; этот сценарий работает и на статическом Pages.

## GitHub Pages

Workflow `.github/workflows/pages.yml` проверяет TypeScript, создаёт статический HTML четырёх страниц и публикует только `frontend/.output-pages/public` после изменений в `main`. В настройках репозитория источник Pages должен быть **GitHub Actions**.

Для локальной сборки достаточно команд ниже; переменные Pages задаются только дочернему процессу и не остаются в PowerShell:

```shell
cd frontend
pnpm build:pages
pnpm check:static
```

По умолчанию это демонстрационная версия для `https://my-eight.github.io/webdev/` с выключенной индексацией. Workflow передаёт адрес из имени владельца и репозитория. При необходимости значения `NUXT_APP_BASE_URL`, `NUXT_PUBLIC_SITE_URL`, `NUXT_PUBLIC_INDEXABLE` можно задать явно в окружении сборки.

Dev, серверная сборка и Pages используют раздельные рабочие каталоги: `.nuxt`, `.nuxt-server`, `.nuxt-pages`; Vite-кэши — `.cache/nuxt/dev`, `server`, `pages`. Результат серверной сборки — `.output`, Pages — `.output-pages`. Можно оставлять `pnpm dev` запущенным во время обеих сборок. Команды `pnpm build` и `pnpm build:pages` выбирают режим только для своего дочернего процесса; `.nuxt` остаётся каталогом типов редактора и обычной разработки.

Если переменные Pages были вручную заданы в текущем окне PowerShell по старой инструкции, перед запуском dev откройте новое окно или удалите их:

```powershell
Remove-Item Env:NUXT_APP_BASE_URL, Env:NUXT_PUBLIC_SITE_URL, Env:NUXT_PUBLIC_INDEXABLE, Env:NITRO_PRESET -ErrorAction SilentlyContinue
```

На Pages используется предварительная генерация HTML; сервер Node.js и будущая логика Go там не выполняются. Настройки окружения встраиваются в HTML во время сборки. Реальные материалы ещё дополняются, поэтому поисковая индексация этой версии выключена явно в workflow. Canonical, метаданные и пути ресурсов учитывают `/webdev/`.

Внутренние Markdown-заметки проекта, зависимости, локальные настройки, кэши и скриншоты не входят в публичный репозиторий и сайт. Изображения превью ссылок находятся в `frontend/public/social`, генератор — `frontend/scripts/generate-social.mjs`. Цвета он читает из `tokens.css`; шрифты HS_LunaObscura и Exo 2 Regular с кириллицей и лицензиями OFL включены в `frontend/scripts/assets/`, системные шрифты отключены. После изменения палитры или макета выполните `pnpm generate:social`. `pnpm check:social` проверяет совпадение готовых PNG с генерацией; такая же проверка выполняется в Linux CI.

## Правило индексации

Проект пока закрыт от индексации. Сохраняем `NUXT_PUBLIC_INDEXABLE=false` до выполнения обоих условий: сайт опубликован и проверен на боевом сервере с основным доменом; все публичные тексты и метаданные повторно проверены на SEO и GEO, точность фактов и соответствие предложению. Обычный деплой и переезд на VPS/VDS сами по себе не включают индексацию.

После этих проверок индексация включается только для боевого окружения с повторной проверкой HTML, HTTP-заголовков, robots.txt, sitemap и canonical. Локальная разработка и демонстрационные/тестовые окружения остаются закрытыми. До окончательного запуска автоматические технические проверки не заменяют проверку всех текстов.

## Проверки

- `pnpm typecheck` — проверка типов.
- `pnpm check:typography` — неразрывные связи предлогов, тексты без точек и сохранность email, URL и технических названий.
- `pnpm check:social` — воспроизводимость изображений превью без системных шрифтов.
- `pnpm build` и `pnpm check:seo` — серверная сборка и проверка SEO для будущего серверного размещения.
- `pnpm build:pages` и `pnpm check:static` — сборка для Pages, проверка HTML, метаданных, ссылок и ресурсов.
- `pnpm check:release` — проверка домена, контактов и включённой индексации перед окончательным публичным запуском.

GitHub Pages обслуживает сайт внутри общего домена пользователя. Для полноценного управления корневым `robots.txt` в дальнейшем нужен собственный домен либо настройка корневого сайта аккаунта; метатег `noindex` уже находится в HTML каждой страницы.

## Визуальная система

На мобильных экранах основной CTA закреплён снизу в `MobileActionBar`: выбор направления на главной, переход к контактам на детальных страницах. Учтены safe-area и отступ в конце документа; обычный CTA в hero виден на широком экране.

Exo 2 подключён локально через `@fontsource-variable/exo-2`, с кириллицей и переменной насыщенностью 100–900; внешних запросов к Google Fonts при просмотре сайта нет. Источник и лицензия статической копии для превью находятся в `frontend/scripts/assets/Exo2-source.txt` и `Exo2-OFL.txt`.

Публичные текстовые поля проходят общее форматирование `frontend/shared/utils/typography.ts`: предлоги связаны со следующим словом, точки в обычном тексте убраны. Правило применяется при SSR, в метаданных и изображениях превью; адреса ссылок и контактов сохраняются.

Чёрный фон и модульная сетка; разработка — кислотный лайм, МойСклад — электрический синий, дизайн — фуксия. Главная объединяет три направления. Заголовки и логотип — HS_LunaObscura, основной текст — Exo 2. Оба шрифта поставляются локально по SIL OFL 1.1. HS_LunaObscura создан [Headspace Agency](https://lunaobscura.headspace.ru/); оригинальный WOFF2, лицензия и источник находятся в `frontend/app/assets/fonts/`. Для генератора изображений в `scripts/assets/` включена TTF-копия того же шрифта без изменения глифов. Конвертация нужна только при замене исходного шрифта, при сборке дополнительные инструменты не требуются.

В hero направлений используются реалистичные портреты самураев по грудь без видимого лица и оружия (`SamuraiPortrait.vue`); на главной три образа собраны в `SamuraiEnsemble.vue`. Прежние геометрические SVG-композиции удалены. Название направления теперь крупное и акцентное, слоган — меньшая белая строка, дополнительная hero-ссылка убрана. Логотип — в `BrandLogo.vue`. Анимации CSS имеют статичное представление при `prefers-reduced-motion`. Хедер закреплён и включает более прозрачное стекло после начала прокрутки: blur 14 px и фон 48%. Основные кнопки имеют общую высоту 40 px, равную знаку логотипа. Анимационные полосы уменьшены до 52 px вместе с внутренней графикой. Статичная сетка слегка приглушена, подсветка при наведении сохранена.

В стилях стекла сначала указывается `-webkit-backdrop-filter`, затем стандартный `backdrop-filter`: обратный порядок приводит к потере стандартного свойства при минификации. `scripts/assert-glass-css.mjs` в составе `check:static` проверяет оба объявления в готовом CSS хедера, мобильного меню и нижней панели действий.

Навигация по секциям направлений хранится в `frontend/app/config/site.ts` (`navigation[].sections`) и доступна через хедер: hover на широком экране, отдельные кнопки раскрытия до 1200 px. Ссылки содержат путь направления и якорь, работают с любой страницы. Декоративный `DirectionRibbon.vue` выбирает поток набираемого кода (`CodeStream`), обмен JSON/API и документами (`DataStream`) или ленту айдентики с типографикой, палитрами, векторными узлами и мини-макетами (`IdentityStream`). Анимации приостанавливаются вне экрана и в скрытой вкладке, при `prefers-reduced-motion` остаётся статический вариант.

Размеры основного текста и заголовков задаются в `tokens.css`: содержание — 17 px, межстрочный интервал — 1,5 (hero — 1,4), вспомогательные подписи — 15 px, заголовки карточек — 20/18 px. Для увеличенной навигации хедер сворачивается до 1200 px включительно. Повторные мелкие приписки под секциями убраны, существенные условия находятся в основном содержании.

## Демонстрационный мини-квиз


На каждой странице направления сразу после FAQ расположен квиз из семи вопросов. Данные вопросов — `frontend/app/data/quizzes.ts`, типы — `app/types/quiz.ts`, интерфейс и локальное состояние — `app/features/quiz/ProjectQuiz.vue`, оформление — `app/assets/styles/components/quiz.css`.

Доступны одиночный и множественный выбор, возврат к ответам, прогресс и контактный шаг. Варианты «Начинаем с нуля» и «Помогите определиться» исключают несовместимые ответы. После прохождения сам блок заменяется результатом с номером `ДЕМО-…` и образцом сообщения о сроке ответа в один рабочий день. Это явно обозначенный демо-режим: запросов к API, сохранения в браузере и реальной отправки нет; при перезагрузке ответы исчезают. Работает и в статической сборке Pages. SSR-представление и расположение квизов проверяются общим `scripts/assert-quiz.mjs` в составе `check:seo` и `check:static`.

## Эффекты прокрутки и интерактивная сетка

FAQ направлений собран в общую непрозрачную панель: на широком экране список вопросов слева и один ответ справа, на телефоне ответ раскрывается под выбранным вопросом. Первый вопрос выбран по умолчанию. Крупный повтор вопроса в ответе убран, сам ответ светлый. Высота и позиции вопросов на широком экране не меняются при переключении; все ответы присутствуют в SSR, скрытые панели исключены из фокуса. Проверки — `scripts/assert-faq.mjs` в составе `check:seo` и `check:static`.

Общий `useScrollReveal` подключён в основном layout: заголовки, карточки, этапы, FAQ, квиз и контакты появляются один раз при входе в экран. Направление, небольшой наклон, длительность и задержка варьируются. Используются IntersectionObserver и Web Animations API; исходный HTML и начальный экран видимы без JavaScript. При переходах между страницами учитывается восстановление прокрутки. При клавиатурном фокусе элемент показывается сразу; при `prefers-reduced-motion` скрытых блоков и входящих анимаций нет.

Текст появляющихся блоков быстро набирается по буквам, а ответ FAQ повторяет эффект при выборе нового вопроса. `app/utils/typewriter.ts` скрывает ещё не открытый хвост текста через [CSS Custom Highlight API](https://developer.chrome.com/docs/modern-web-guidance/guides/ui-behaviors/highlight-text-ranges): сам текст, его переносы и высота остаются полными, Vue-разметка не переписывается, экранный диктор получает весь текст сразу. Используется один requestAnimationFrame для активных фрагментов, длительность 240–1100 мс; Unicode разбивается по графемам. Старый набор отменяется при переключении, уходе со страницы, изменении содержания и фокусе; при reduced motion, печати, скрытии вкладки и изменении размера полный текст показывается сразу. Браузер без поддержки API выводит обычный текст. Ввод, кнопки квиза и навигация не задерживаются набором.

`InteractiveGrid.vue` добавляет мягкий световой след по линиям фоновой сетки. Размер ячеек общий с фоном, смещение согласовано с прокруткой; на главной подсветка трёхцветная, на направлениях — в их акценте. Эффект включается для мыши при точном указателе и hover, отключается при уменьшении движения. Координаты обновляются через requestAnimationFrame без перерисовки Vue-компонентов; после остановки следа цикл обновления координат прекращается. Стили общих эффектов — `components/site-motion.css`.


Первый экран всех страниц объединяет hero и полосу в `.first-screen`: высота рассчитывается через `100dvh` с резервным `100svh`, за вычетом хедера и мобильного CTA. На главной полоса объединяет три направления. В короткой альбомной ориентации hero переключается в две колонки. Контент расширен до 1440 px с более узкими боковыми полями. Заголовок направления называется «Разработка»; публичный путь `/web-development` сохранён.

CTA хедера и hero используют один `button button-primary`, включая отступы, толщину текста и стрелку: одинаковая надпись даёт одинаковый размер. Отдельные размерные стили для `.header-contact` не нужны.


## Самураи в hero

Три изображения созданы встроенным image_gen по отдельным промптам после просмотра визуальных референсов Pinterest. Изображения Pinterest не включены в сайт. У разработки — технический плащ и лаймовый свет, у МойСклад — традиционная броня и синий свет, у дизайна — женский силуэт, отдельный скульптурный костюм и фуксия. Все портреты по грудь, без лица, рук и видимого оружия, в классических металлических шляпах. Финальный набор промптов и ссылки на вдохновение — `frontend/scripts/assets/samurai-prompts.json`.

Готовые прозрачные WebP находятся в `frontend/public/images/samurai/`, метаданные — `app/data/samurai-assets.json`. Для каждого образа есть480/800/1200px; srcset выбирает размер под экран. Имена содержат отпечаток исходника, поэтому новая версия не подменяется старой картинкой из кэша. Исходные PNG и отклонённые варианты остаются локальными, в публикацию не входят. Для подготовки новых PNG с именами development.png, moysklad.png и design.png выполните из frontend: `pnpm prepare:samurai <папка-с-исходниками>`. Sharp нужен только этому этапу подготовки; браузер и GitHub Pages не требуют Node.js или 3D-движка.

`components/samurai.css` добавляет блики по реальным пикселям шляпы и костюма, слабый световой фон и отклик на мышь. Слои используют один и тот же srcset и кэш изображения. Анимации стоят на паузе вне экрана и в скрытой вкладке; при reduced motion нет бликов, частиц и наклона. Мобильная версия сохраняет читаемый текст и нижний CTA, фоновые портреты не перехватывают касания.
